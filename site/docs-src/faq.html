FAQ and troubleshooting

Questions · Troubleshooting

Questions

Is it a VPN?
No. A VPN hides your browsing by sending it through someone else's server. A pen is a private place with its own sites and its own guest list. Your normal browsing keeps going straight to the internet; only pen names use the pen.
Why not just use Tailscale?
If you're technical and only want your own devices connected, do. Hogman is built on Tailscale's open-source pieces and runs alongside it. Hogman is for a private place for a group of people: guests join from a link, the keeper runs the guest list from a web page, every pen has its own names and real browser HTTPS without exposing any site IPs (though hostnames appear in public Certificate Transparency logs; contents never do).
Can strangers find my pen?
No. Pen names have zero public A/AAAA records (ns1.hogman.network returns empty NODATA except for temporary ACME validation tokens), and the addresses inside the mesh aren't routable from the internet. The only public part is each pen's control address (<pen>.gate.hogman.network): it serves the join page and lets in devices that hold a valid key, nothing more.
Can AI companies or data brokers get what's in my pen?
Not from the pen itself. AI training data comes from crawlers on the public web, and a pen's sites have no public address, so there's nothing to crawl. Data brokers live on ads, trackers and data sold by apps; Hogman has no ads, trackers or analytics, sells nothing, and keeps as little as it can. What a pen can't stop: a member copying something out (a screenshot, a paste into a chatbot), an app you install in your pen that sends data home on its own, and pen and site hostnames showing up in public Certificate Transparency logs (hostnames only, never what's on the sites; pen names are never reused, D-21).
Can the keeper read what I send?
No. Traffic between members is WireGuard + TLS 1.3 encrypted end to end. The keeper (and us as host) can see who's in the pen, their devices, and which pen names get looked up. Who sees what.
Do I have to install a custom root certificate?
No. Hogman uses standard public web certificates issued over ACME DNS-01 and trusted by your browser and operating system automatically (D-18, D-22). Nothing is added to your trust store, so no pen can sign for outside sites. If you joined an older release before public certificates, ./hogman-join update and leave remove that old root certificate automatically, and older private-CA pens must be recreated.
Can I be in more than one pen?
Yes. Join each with its own link. Each pen gets its own background connection and proxy, and they run at the same time. Browser isolation note (D-19): because hosted pens share pens.hogman.network until Public Suffix List inclusion, browsers treat pens as sibling subdomains for cookies and same-site requests. If you join a pen you don't fully trust, use a separate browser profile for it.
What does Hogman deliberately not do?
Anything but HTTPS. No ssh, no other ports, no games or voice over UDP. Your computer joins only as a visitor: it can't be turned into a server for the pen, or into a route for the pen's traffic to your home network or the internet, and nobody in the pen can connect to it. Each of those would be one more way in for an attacker, on your computer and on everyone else's in the pen, so they don't exist and there's no setting to turn them on. Things that serve the pen are shares, each a small device of its own.
What if I lose my laptop?
If you still have another device in the pen, remove the lost one under Your devices straight away: its place in the pen is a file in your account, not yet locked to its hardware, so someone who copies that file can use it until it's removed. If you lost every device, your account is gone. There is no account recovery: no recovery page, no password reset and no support route, not even for pens we host, so there is nothing for an attacker to try. Ask a keeper for a new invite and start a new account; they give it back your role and kick the old one. If you run a pen, make a friend a second owner: a pen whose only owner loses every device keeps working, but nobody can manage it again.
Phones?
Not yet. A phone app is in the works.
What does it cost?
Free while we test. Hogman runs hosted-only on hogman.network (D-24); the full code is AGPL-3.0 open source on GitHub.

Troubleshooting

"this link is from an older release (carries fp=)"
Invite and share links from before the public-certificates release no longer work. Ask the keeper or sharer for a fresh link. If the pen itself was created before public certificates, the pen must be recreated.
The browser can't find pen sites
Only programs that use the pen's proxy reach the pen. On a Mac the join sets your automatic proxy setting; if another non-Hogman tool already set one, it leaves yours alone and prints the address to use. If you join multiple pens, each pen's proxy.pac includes all joined pens and Mac updates it automatically; on Linux and Windows, use one printed http://127.0.0.1:<port>/proxy.pac URL and reload proxy settings (or switch to a remaining pen's URL when leaving a pen). For command-line tools, see joining, in practice.
Pen sites say "DNS address could not be found" while my VPN is on
On macOS, Network Extension VPNs (ProtonVPN, Mullvad, WireGuard, corporate VPNs) replace the system automatic proxy setting while connected, so browsers fall back to public DNS — where pen names intentionally do not exist. Your hogman-join connection is still up. Either pause your VPN while visiting pen sites, or configure Firefox's built-in Automatic proxy configuration URL to the address printed by hogman-join so pen names route straight to hogman-join while ordinary browsing stays on your VPN. (A companion browser extension for Chrome, Brave, Edge, and Firefox is available in browser-ext/ for manual developer install while store listings are prepared.)
"This computer cannot find the network's names yet"
Run the same join command again. Your invite was already used to add this device, so the rerun sees the device is in, skips the invite, and goes on to check your home page. (The link won't work on another computer: ask for a device link instead.)
The join tool tried to open a browser on a server
Add --no-open. On a machine with no desktop there's nothing to open; the home page address is printed either way.
"is already being shared from this computer"
That share is already running, perhaps in the background or another window. See it with ./hogman-join share list; stop it with ./hogman-join share stop NAME.
A shared site says "the app isn't answering right now"
The share is up but nothing is listening on the port you gave it. Start your app (or check the port), and reload.
"the invite was not accepted"
Invites work once and expire after 7 days; device links expire after an hour. Ask for a new one. If you picked a name someone already has, the tool asks for another.
I left, and want back in
Leaving takes your devices out, not your membership. Ask the keeper for a device link (or make one yourself from the home page on another device you still have), and join again.

Still stuck? Open an issue on GitHub with what you ran and what it printed.
