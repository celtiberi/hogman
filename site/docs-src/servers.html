Your own web server advanced

You probably don't need this page. Sharing puts any folder or app in the pen with one command, certificates included. This page is for the technically minded who want to run their own web server (Caddy, nginx, anything that speaks ACME) on a machine in the pen, with their own configuration, other ports, or several sites behind one server.

The steps: join the machine as a server, point a name at it, and have your web server get its certificates from the pen's own certificate authority.

1. Join the machine as a server

On your pen's home page, press Add a server and open the link on the machine (or copy the command its page shows into the machine's terminal). It joins as one of your devices, marked as a server, so members can connect to it. Like any join, it uses the machine's Tailscale if it's free, or joins side by side.

2. Give it a name

On the home page, under Names for your servers, claim a name such as blog and pick the machine. It becomes blog.yourpen.hogman for everyone in the pen. Names under a name you own work too (api.blog). If the name is taken, the page says whose it is; names are first come, first served, and a removed member's names are held for 90 days. A device's own automatic name, such as closet-box.nodes.yourpen.hogman, is separate and always works.

3. Point Caddy at the pen's CA

The only pen-specific line is the CA address in Caddy's global options:

{
	acme_ca https://ca.smith.hogman:9000/acme/acme/directory
}

blog.smith.hogman {
	reverse_proxy 127.0.0.1:3000
}

Caddy trusts the pen's CA because the join added its root to the machine. If Caddy runs somewhere that root isn't installed (a container, say), add acme_ca_root /path/to/root_ca.crt; you can download the root from your home page.

Caddy gets a 7-day certificate and renews it by itself. Any other ACME client works the same way: point it at https://ca.yourpen.hogman:9000/acme/acme/directory and use the TLS-ALPN or HTTP challenge.

4. Start it

  • With Tailscale (the machine joined with its own Tailscale): run Caddy as usual.
  • Side by side: the join tool passes the pen's ports 80 and 443 to the machine's own 80 and 443, and Caddy reaches the CA through the join tool's proxy. The join output prints the exact line, for example: 
    $ HTTPS_PROXY=http://127.0.0.1:21234 caddy run

Listening on ports 80 and 443 needs permission on Linux: run Caddy as root (or through systemd), or allow the binary once with sudo setcap cap_net_bind_service=+ep "$(command -v caddy)".

Good to know

  • Servers accept connections from any active member's device, on any port. Personal devices never do.
  • A server can't add devices, invite people or run the pen; use a personal device for that.
  • If the member who owns the server is suspended, the server is cut off until they're resumed. If they're removed, the server is deleted and its names are held for 90 days.
  • Apps that keep their own certificate list (Java, Node, Python) may need the pen's root; see the FAQ.
