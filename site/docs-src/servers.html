Your own web server advanced

Most people don't need this page. If you just want to put a folder or an app in your pen, sharing is one command, certificates included. This page is for running your own web server, such as Caddy or nginx, on an always-on machine, with your own configuration.

What this is · What you need · The steps · Check it works · Details

What this is

You put an always-on machine (a mini PC in the closet, an old laptop, a small cloud server) into your pen as a server, and run a web server on it. People in the pen open it at an address like https://blog.yourpen.hogman, with the padlock; nobody outside can find it.

A server is a device that people in the pen are allowed to connect to. A normal laptop or phone is a personal device and never accepts those connections. That's why this machine joins with Add a server rather than Add a device.

Why do this instead of sharing? You want your own web server's features: several sites or apps behind one server, your own redirects or headers, or a setup you already run elsewhere. It's still HTTPS only: members reach the server on ports 443 and 80, nothing else.

What you need

  • A pen you're a member of, and a computer that's already in it.
  • An always-on machine, Mac or Linux.
  • Caddy installed on it (install guide), or another web server that can get certificates over ACME.
  • About ten minutes.

The steps

The example: a blog app running on the machine at port 3000, in a pen called smith. Put your own pen's name where you see smith.

  1. Get a server link. On a computer that's already in the pen, open your pen's home page (https://home.smith.hogman) and press Add a server. You get a link that works once and expires in an hour.
  2. Join the machine. On the always-on machine, open that link and run the command it shows. It downloads hogman-join and joins the machine as one of your devices, marked as a server. Keep the output: it says how the machine joined, which matters in step 5.
  3. Give it a name. Back on the home page, under Names for your servers, type a short name such as blog and pick the machine. Everyone in the pen can now use blog.smith.hogman.
  4. Tell Caddy where to get its certificate. Your pen has its own certificate authority (CA), the service that hands out the padlock certificates. Caddy normally asks Let's Encrypt; here it asks your pen instead. The Caddyfile: 
    {
	acme_ca https://ca.smith.hogman/acme/acme/directory
}

blog.smith.hogman {
	reverse_proxy 127.0.0.1:3000
}
    The first block points Caddy at your pen's CA. The second says: when someone opens blog.smith.hogman, pass the request to the app on this machine at port 3000. For a plain folder of files instead, use: 
    blog.smith.hogman {
	root * /var/www/blog
	file_server
}
  5. Start Caddy. Caddy reaches the pen's CA through the join tool's local proxy. The join output printed the exact line, for example: 
    $ sudo HTTPS_PROXY=http://127.0.0.1:21234 caddy run
    Set that proxy only for Caddy, not for the whole machine: it only works for names inside the pen. The join tool passes visitors on the pen's ports 80 and 443 to the same ports on this machine, where Caddy is listening. On Linux, only root may use ports 80 and 443, hence sudo. To run Caddy as a normal user instead, allow it once: sudo setcap cap_net_bind_service=+ep "$(command -v caddy)".

Check it works

From another computer in the pen, open https://blog.smith.hogman. You should see your site with the padlock. The first visit can take a few seconds while Caddy gets its certificate; after that it renews by itself (certificates last 7 days).

Details

Names
Names are first come, first served; if one is taken, the page says who has it. Once blog is yours you can also claim names under it, like api.blog. A removed member's names stay reserved for 90 days so nobody can pretend to be them. Every device also has an automatic name, like closet-box.nodes.smith.hogman, which always works but isn't the one you'd give people.
Other ACME tools
Anything that can get certificates the way it would from Let's Encrypt (ACME) works: point it at https://ca.smith.hogman/acme/acme/directory. It proves it controls the name over port 80 (HTTP) or 443 (TLS), as on the public internet, but only inside the pen.
Certificates in containers
When the machine joined, Hogman installed your pen's root certificate on it, so Caddy already trusts the pen's CA. If Caddy runs in a container that doesn't have it, download root_ca.crt from your home page and add acme_ca_root /path/to/root_ca.crt to the first block.
Who can reach the server
Any active member's device, on ports 443 and 80 only. A server can't add devices, invite people or run the pen; do that from a personal device.
If the owner is suspended or removed
Suspended: the server is cut off until they're resumed. Removed: the server is deleted and its names are held for 90 days.
Apps with their own certificate lists
Java, Node and Python may need to be told about the pen's root; see the FAQ.
