Onboarding staff & devices

How employees and contractors connect a Mac or Linux laptop to a pen using a single-use invite link — without routing ordinary browsing through a VPN.

Connecting a first workstation

  1. Open the invite link on the workstation that needs access. Invite links work once and expire after 7 days.
  2. Run the setup command shown on the page in Terminal — it is the same short command for everyone in the pen: 
    $ curl -fsSL https://store-north.gate.hogman.network/start | sh
    The script prompts for the invite link (use the page's Copy my invite link button), downloads hogman-join for the platform, verifies its published SHA-256 checksum, saves it as ~/hogman-join, and runs it. The invite token never appears in shell arguments or history. Inspect the script first, or expand the manual download steps on the join page.
  3. Choose a handle when prompted (lowercase letters, digits, and dashes, 2–32 characters — for example, alex-ops).
  4. Confirm access. hogman-join verifies the gate against the operating system's built-in HTTPS trust store, confirms the pen portal loads over HTTPS, configures the browser proxy, and opens it. Keep ~/hogman-join on the machine for updates, hosting, and disconnecting later.

Expected macOS prompts during first setup:

  • "Allow hogman-join to find devices on local networks?" Either choice works. Allow lets devices on the same LAN connect directly over WireGuard; Don't Allow routes encrypted traffic through the relay instead. Nothing on the local LAN is exposed either way.
  • Your Mac's password, once, to configure the system automatic proxy URL so browsers resolve pen hostnames. If skipped, hogman-join prints the PAC URL to configure manually.

If setup is interrupted partway (offline or DNS still propagating), resolve the issue and run the same command again. If it stopped before redeeming the invite, the link remains unused; if after, the rerun detects the enrolled workstation and finishes setup.

Using alongside a corporate VPN

On macOS, Network Extension VPN clients (corporate VPNs, WireGuard, ProtonVPN, Mullvad) override the system automatic proxy setting while connected, so browsers stop resolving pen hostnames even though hogman-join stays connected.

  • Firefox (works today, no extension required): set Firefox's built-in Settings → Network Settings → Automatic proxy configuration URL to the http://127.0.0.1:<port>/proxy.pac URL printed by hogman-join. Pen hostnames route through hogman-join while ordinary browsing stays on the VPN.
  • Chrome, Brave, Edge, and Firefox extension (developer preview): the companion extension in browser-ext/ is not yet published on the Chrome Web Store or Mozilla Add-ons. Teams can load it manually from browser-ext/dist/ (see browser-ext/README.md; note that Firefox removes temporary add-ons on restart, and Firefox Private Windows send pen names to public DNS unless Run in Private Windows is enabled for the extension).
  • Safari: Apple does not expose proxy APIs to Safari extensions, so pause the VPN while accessing pen dashboards in Safari.

How the client connects

hogman-join runs a small unprivileged userspace process as the logged-in user (no TUN interface, no root daemon) that starts at login. It carries HTTPS (port 443) to pen servers and nothing else (plain http:// requests redirect locally to HTTPS). Regular internet browsing, local LAN access, and any existing Tailscale installation remain untouched. See what Hogman deliberately does not do.

Browsers and command-line tools

Only applications configured to use the pen's loopback proxy (e.g. http://127.0.0.1:21234) can reach pen sites:

  • Browsers: on macOS, hogman-join sets the automatic proxy URL (never overwriting an existing non-Hogman proxy). Joining multiple site pens updates one combined proxy.pac automatically. On Linux, point the browser or desktop automatic proxy setting to the printed proxy.pac URL (one URL covers all joined pens; reload proxy settings after joining or leaving a pen).
  • curl (per command): 
    $ https_proxy=http://127.0.0.1:21234 curl https://cooler-1.store-north.pens.hogman.network
    Do not export https_proxy globally in your shell — the proxy refuses all non-pen hostnames.
  • git (per host): 
    $ git config --global http.https://git.store-north.pens.hogman.network/.proxy http://127.0.0.1:21234

Adding a second workstation

From the pen's portal, press Add a device to generate a single-use link and QR code (valid for 1 hour). Open it on the second laptop and run the setup command; it enrolls under the same member account. Mobile support is in progress.

For an always-on on-site bridge or server, do not use a personal device link — use a share link as documented in Bridging equipment & apps.

Updating and disconnecting

$ ~/hogman-join update

Fetches the latest binary from the pen's gate (or a specified host), verifies its SHA-256 against SHA256SUMS over HTTPS, restarts the background agent and service-managed bridges, and cleans up legacy state. Pass --pen ZONE when connected to multiple pens, or --dry-run to preview.

$ ~/hogman-join leave '<your pen link or zone>'

Stops any bridges running on that machine, shuts down the background connection, and clears its proxy configuration. Membership remains active — owners and admins remove accounts from the portal.
