The problem

Operational devices don't belong on the public internet.

In 2026, attackers remotely hijacked internet-exposed supermarket refrigeration and freezer controllers across Europe — spoiling food and causing fires. The root mistake wasn't a single bad password; it was leaving equipment control panels reachable from the open internet at all.

Invisible from the outside

Sites inside a pen have no public IP addresses and no public A/AAAA DNS records. Internet scanners, bots, and opportunists can't reach a login page they can't even resolve.

Standard browser HTTPS

Authorized staff open internal dashboards in Chrome, Safari, or Firefox with real domain names and standard HTTPS certificates — no shared corporate VPN routing everyone's ordinary browsing, and no custom root CA to install.

Instant offboarding

Manage your guest list from a single web page inside the pen. When a contractor finishes a job or an employee leaves, kicking them cuts off every device they used in about two seconds and permanently retires their names.

How it works

How to put an equipment controller in a pen

Equipment like refrigeration controllers, HVAC panels, and cameras can't install client software themselves. You keep them strictly on your local network and bridge their web interface into your pen with a small always-on computer on site.

  1. 1

    Close the router ports

    Remove any public IP mapping or router port-forwarding pointing at the device. Its web interface should only answer on your local LAN (for example, http://192.168.1.40).

  2. 2

    Bridge the device from a small on-site computer

    Place an inexpensive, always-on Linux or Mac box (like a Raspberry Pi or mini PC) on the same local network. Using a one-time share link from your pen's home page, run one command to expose only that controller's web UI inside the pen over HTTPS: 

    ~/hogman-join share cooler-1 http://192.168.1.40 --background '<share-link>'

    The bridge joins as an isolated server node carrying HTTPS (port 443) only. Zero inbound ports are opened on your firewall, and nothing else on your LAN is exposed.

  3. 3

    Give staff invite links — and separate pens by site

    Send each manager or technician a single-use invite link. Running multiple locations? Create a separate pen per region or store group (for example, region-north.pens.hogman.network and region-south.pens.hogman.network) so a single stolen laptop or compromised account can never reach every store.

Plain-English security boundaries

What a pen does — and what it doesn't do

We'd rather tell you the exact limits up front than sell magic security claims. Read the complete breakdown in Architecture & security.

Hides vulnerable devices — does not patch them

A pen removes your equipment from the public internet and restricts reachability to invited pen members. It does not fix bugs in device firmware. Keep your vendor security updates turned on and change default device passwords.

HTTPS web interfaces only (port 443)

Pens carry HTTPS (port 443) to shared servers and nothing else — no SSH, no raw TCP/UDP ports, no exit nodes, and zero inbound connections to staff laptops. Devices that only speak raw non-HTTP protocols without a web UI aren't a fit.

Separate pens for separate locations

For multi-site operations, put each region or store group in its own pen so one lost laptop doesn't expose every facility. Until pens.hogman.network is listed on the Public Suffix List, use a separate browser profile for any pen you don't fully trust.

Zero account recovery — appoint two owners

There is no support backdoor to unlock a pen. If the only owner loses every device, nobody can manage that pen again. Always appoint a second trusted owner in The herd right after setup.

Hostnames in public Certificate Transparency logs

Standard public HTTPS certificates mean pen and site hostnames (never site contents or IPs) appear in public CT logs. Use generic site labels like cooler-1 rather than sensitive customer or address details in hostnames.

Experimental testbed today

Hogman is young open-source security software (AGPL-3.0, SLSA-attested releases) and has not yet had an independent security audit. macOS and Linux work today; Windows and mobile apps are not ready yet. Evaluate carefully before relying on it for safety-critical systems.
