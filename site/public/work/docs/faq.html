FAQ & troubleshooting

Straight answers to the questions people ask first, plus fixes for the errors you might actually hit.

Frequently asked questions

Why not just use Tailscale?
If you only want your own devices connected, do — Hogman is built on Tailscale's open-source tsnet and runs cleanly alongside it. Hogman is for running a private web for a group of people: guests join from a single-use link, you manage the herd from a web page, and every site gets real domain names and standard HTTPS with zero public IPs.
Can I self-host a Hogman pen server?
Hogman runs pen control planes hosted-only on hogman.network (we don't support self-hosted pen servers or custom pen domains). Your web apps and files still run on your own machines via hogman-join share over end-to-end encrypted WireGuard. The entire codebase is AGPL-3.0 on GitHub with SLSA-attested releases (gh attestation verify hogman-join --repo celtiberi/hogman), and operators can read the operator guide to see exactly how our host runs.
Is it a VPN?
No. A VPN sends all of your browsing through someone else's server. A pen is a private web with its own names, HTTPS sites, and guest list — your regular internet keeps going straight out as usual.
What does Hogman deliberately not do?
Anything other than HTTPS (port 443). No SSH, no raw TCP/UDP ports, no exit nodes, and no inbound connections to personal laptops. Every extra protocol is another attack surface on everyone's computer, so they don't exist and there's no toggle to turn them on. Web servers join as separate isolated share nodes.
Can strangers, AI crawlers, or data brokers find my pen?
No. Pen names have zero public A/AAAA records (ns1.hogman.network returns empty NODATA except for temporary ACME challenge tokens), and mesh IPs aren't routable from the internet. Hogman adds zero ads, trackers, or analytics anywhere. What a pen can't stop: a member screenshotting or pasting content out, a third-party app you run phoning home, or site hostnames appearing in public Certificate Transparency logs (names only, never site contents).
Can the keeper or Hogman read what we send?
Not passively. Traffic between devices is encrypted end to end with WireGuard + TLS 1.3. The keeper and our control plane can see membership, devices, and mesh DNS lookups, and control admission/DNS-01 — see the full threat model.
Can I be in more than one pen?
Yes — join each with its own invite link. Their local proxies run side by side and share one combined proxy.pac. Until pens.hogman.network is listed on the Public Suffix List, use a separate browser profile for any pen you don't fully trust so cookies stay isolated.
What if I lose my laptop?
If you have another device in the pen, remove the lost one under Your devices immediately (pen credentials live in user-readable state files on disk). If you lose every device, your account is gone: there is no account recovery and no support backdoor. Ask a keeper for a new invite, restore your role, and kick the old account. If you own a pen, appoint a second owner.
Phones, Windows, and cost?
Free while we test. macOS and Linux work today; Windows is built but untested, and a phone app is in the works.

Troubleshooting

Pen sites say "DNS address could not be found" while my VPN is on
On macOS, Network Extension VPNs (ProtonVPN, Mullvad, WireGuard, corporate VPNs) replace the system automatic proxy setting while connected, so browsers fall back to public DNS — where pen names intentionally do not exist. Your hogman-join connection is still up. Either pause your VPN while visiting pen sites, or configure Firefox's built-in Automatic proxy configuration URL to the address printed by hogman-join so pen names route straight to hogman-join while ordinary browsing stays on your VPN. (A companion browser extension for Chrome, Brave, Edge, and Firefox is available in browser-ext/ for manual developer install while store listings are prepared.)
The browser can't find pen sites (no VPN running)
Only programs using the pen's local proxy reach the pen. On macOS, hogman-join sets the automatic proxy URL automatically unless another non-Hogman proxy is already set (in which case it prints the URL for you to configure). On Linux, point your browser's automatic proxy setting to the printed http://127.0.0.1:<port>/proxy.pac URL and reload proxy settings after joining or leaving a pen. For CLI tools, see Browsers & CLI tools.
"This computer cannot find the network's names yet"
Run the same join command again. Your invite was already used to enroll this device, so the rerun skips invite redemption and finishes verifying your home page. (That invite won't work on a second computer — use Add a device instead.)
The join tool tried to open a browser on a headless server
Pass --no-open. The home page URL is still printed to the terminal.
"is already being shared from this computer"
That share is already running in the background or another terminal. Inspect with ~/hogman-join share list and stop with ~/hogman-join share stop NAME.
A shared site says "the app isn't answering right now"
The share node is up, but nothing is listening on the local port you specified. Start your web server (or double-check the port) and reload.
"the invite was not accepted"
Invites work once and expire after 7 days; device and share links expire after 1 hour. Ask for a fresh link.
I left, and want back in
leave removes your device, not your membership. Ask a keeper for a device link (or generate one from another device you still have in the pen) and join again.
"this link is from an older release (carries fp=)"
Links from early private-CA test builds (before public certificates) are rejected. Ask the keeper for a fresh link; pre-switchover .hogman pens must be recreated.

Still stuck? Open an issue on GitHub with what you ran and the exact output.
