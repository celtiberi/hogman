- `.github/workflows/release.yml`, `deploy/release.sh`, & `deploy/README.md`: releases are now published by a GitHub workflow started by hand and approved in a protected `release` environment, not from a maintainer's machine. It releases only a commit on `main` with successful `build`, `e2e` and `vuln` runs, and gives the packaged archives, installer and client binaries GitHub build provenance before publishing. `release.sh` gained a package-only / publish-those-files split (`NO_DEPLOY=1 OUT_DIR=…`, then `PUBLISH_FROM=…`) so the attested files are the published ones; publishing refuses files whose checksums, version or installer don't match the commit.
