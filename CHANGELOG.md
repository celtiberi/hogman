### Added

- `deploy/hogman-watch.sh` watches two more things on a pen with public certificates: the challenge DNS (every name server for the pens zone must answer for it with authority; needs `dig`) and the certificate's expiry, now judged by its lifetime (an alert with a quarter left, at most 30 days, instead of a flat 14), so a `*.gate` wildcard that stops renewing is caught about a week after renewal should have happened. Pull requests that touch only DNS records (`infra/`) or the DNS and site-deploy workflows skip the e2e suites.

- Browser extension (`browser-ext/`, developer preview — not yet published to Chrome Web Store or Mozilla AMO) for Chrome, Brave, Edge, and Firefox 128+ (Manifest V3) to route `*.pens.hogman.network` straight to the local `hogman-join` proxy alongside OS VPNs (ProtonVPN, Mullvad, corporate VPNs) while keeping ordinary browsing on the VPN:

  - Documented macOS VPN coexistence (pausing VPN, Firefox built-in PAC URL, Safari note, and developer preview extension status) on the join page (`core/join-page/`), `/docs/join.html`, `/docs/faq.html`, and `/docs/security.html` (also aligning the macOS password-prompt note).

### Added
- Public-certificate client and share ACME DNS-01 support (D-18, step 3): `core/join` validates explicit public-certificate network zones client-side (matching `<pen>.pens.<base>` for `*.gate.<base>` gates or strict subdomains of the invite host's registrable domain for self-hosted gates), omits OS trust-store installs when joining or leaving public-certificate pens, verifies `https://home.<zone>` against system trusted roots before configuring browser proxies (rolling back fresh joins on failure), and obtains/renews `hogman-join share` certificates via CertMagic DNS-01 over `/api/acme/txt` with persistent `<shareDir>/acme` caching, exponential startup backoff, and lazy single-use EAB failover via `/api/acme/eab` on CA rate limits/outages (never on DNS errors). Updated `core/join-page/join.js` and `core/registrar` links/`NetworkInfo` to handle public-certificate links without `fp=`, and extended `core/test/acme-pebble.sh` with offline Pebble share issuance, cache reuse, ownership enforcement, and failover e2e coverage. Not enabled on hosted pens until the switch-over.
- Public pens from `hogman-host` (D-18 switch-over, Phase B items 3 and 4): `hogman-host add <pen>` makes a public-certificate pen whose front door is `<pen>.<gate-domain>` and whose sites live under `<pen>.<pens-zone>`, set once with the new `hogman-host pens-zone <zone>`. The `--public` option is gone. With a pens zone set, sign-ups raise public pens too: links carry no `fp=`, no root key is escrowed, and the result reports the real zone. The sign-up broker can now reach the challenge DNS server (without it every public sign-up would fail), and the sign-up page shows names under the pens zone. `deploy/test-host.sh` now runs a public pen and a public sign-up end to end, against the real challenge DNS server and Pebble.
- Fixed: `hogman-host gate-cert-setup` now creates the `hogman-pen` system user (uid 65532) and runs `hogman-gate-cert` as it. systemd refuses a bare uid with no account (217/USER), so the service never started.
- The front door's wildcard (D-18, step 4b): `hogman-host gate-cert-setup <gate-domain>` runs `registrar gate-cert` as a locked-down service (uid 65532, no capabilities, `ProtectSystem=strict`, the host credential through `LoadCredential`). It keeps `*.<gate-domain>` by DNS-01 through challenge-dns, and a systemd path unit reloads the front door when the certificate changes. The front door serves the wildcard for pens under the gate domain, and only once the files exist. It doesn't start until the challenge name is delegated, to stay clear of Let's Encrypt's failure limits. The registrar's certificate manager can now certify any name (`Host`, `FileBase`).
- Pens with public certificates (D-18, step 4a), internal groundwork for the switch-over, not a user setting (D-22): `CERT_MODE=public` in a pen's `.env`, with `ZONE` such as `bobo.pens.hogman.network`, runs without step-ca or a root (`compose.public.yaml`). The registrar gets `home.<zone>`'s certificate by DNS-01 through the host's challenge DNS server, and the portal serves it (`portal.public.Caddyfile`, admin socket for reloads). An undocumented `hogman-host add … --public <zone>` makes the pen's scoped challenge DNS credential and refuses names ever used before (failing closed). `remove` drops the credential and keeps only the name. A CI check guards the combined compose files. Not used until the switch-over.
- `hogman-host challenge-dns-setup <public-ip> [gcp-key.json]` runs the DNS-01 challenge server as a locked-down systemd service: its own nologin system user, a persistent API socket folder for the registrars (tmpfiles.d), `CAP_NET_BIND_SERVICE` only, `ProtectSystem=strict`, a syscall filter, and the Google key handed over as a systemd credential. It opens 53/tcp and 53/udp in UFW. `hogman-host challenge-dns …` runs its CLI. Its state is in the nightly encrypted backups. Not used by pens until the switch-over.
- `core/registrar` ACME DNS-01 support (D-18, step 2): when configured with `CHALLENGE_DNS_URL` and `HOME_TLS_DIR`, the registrar obtains and renews `home.<zone>` itself via CertMagic (with optional lazy single-use EAB failover to `ACME_FALLBACK_CA_URL` on CA rate limits/outages, never on DNS failures), writes `home.crt`/`home.key` atomically into `HOME_TLS_DIR`, triggers hot-reload of portal Caddy over `CADDY_ADMIN_SOCKET`, checks `home.<zone>` cert validity in `registrar health`, and supports forced renewal on `SIGHUP`. Mesh `POST/DELETE /api/acme/txt` and `POST /api/acme/eab` endpoints let `server` devices write/remove DNS-01 records only for names they own (and mint fallback EAB credentials once owning at least one claimed name), refusing personal devices, other members/devices, and reserved labels (`home`, `nodes`, `ns[0-9]*`, `_acme-challenge`). Legacy `ROOT_CA` `step-ca` defaults remain intact when `CHALLENGE_DNS_URL` and `HOME_TLS_DIR` are unset. Covered by registrar unit tests and an offline Pebble + `pebble-challtestsrv` Docker e2e suite (`core/test/acme-pebble.sh`).
- `deploy/challenge-dns` (D-18, step 1): the authoritative DNS server for ACME DNS-01 challenges under `pens.hogman.network` and the front door's wildcard name. It serves only challenge TXT records, CAA, SOA and NS, never addresses. It answers NODATA rather than NXDOMAIN under its zones (RFC 8020), and refuses everything outside them. Each pen's credential can write only that pen's challenge names, capped at 10 new names a week; tokens are stored hashed. Single-use Google Trust Services account keys are minted on request for the fallback CA. Built by CI with provenance, and scanned by govulncheck. Not yet deployed or used.

### Security (audit quick wins, docs/security/audit-2026-11.md)
- Caddy & front-door hardening (audit H3, D-19): all Caddy containers (`edge`, `portal`, and `hogman-host` shared `front`) run non-root (`HOGMAN_UID:HOGMAN_GID` / `65532:65532` on root hosts), read-only with `cap_drop: [ALL]` and `no-new-privileges`, using unprivileged port binding (`sysctls` / netns) and `tmpfs` `/tmp`; both the shared front door and per-pen `edge` replace the Headscale catch-all proxy with an explicit allow-list (`/ts2021`, `/key`, `/derp`, `/derp/probe`, `/derp/latency-check`, `/bootstrap-dns`, `/machine/ping-response`, `/health`, returning `404` on everything else), add `X-Content-Type-Options: nosniff` on `/join/dl/*` and `/hogman/*`, and send `Origin-Agent-Cluster: ?1` on Hogman pages (`/join`, `home.<zone>`, sign-up, and website).
- Registrar (audit H2): the member and admin API trusts X-Forwarded-For to say who is asking, so in a pen it no longer listens on loopback TCP, where step-ca and anything else sharing the namespace could reach it and claim to be any member. It listens on a Unix socket in `data/api`, mounted only into the registrar and the portal (`MESH_ADDR=unix:…`); the kernel enforces who can connect.
- Releases (audit H5): compiled parts come only from GitHub's build of the exact commit being released, never from a laptop. Every compiled file carries signed SLSA build provenance (GitHub artifact attestations); `deploy/release.sh` refuses to publish unless each file verifies against `build.yml` and the release commit. Anyone can check a file with `gh attestation verify FILE --repo celtiberi/hogman`.
- Sign-up & redeem rate limits (audit H8): `POST /api/create` validates the sign-up code, pen name, and server capacity synchronously before queueing a background job; `jobStore` caps open/stored jobs, keeps completed results re-readable for 5 minutes after first delivery (30-minute unread cap), then deletes them (`GET /api/job`), and adds HTTP server idle timeouts; wait-list joins and `ntfy` pushes are globally capped; and both sign-up and registrar (`/hogman/v1/redeem`) rate limiters group IPv6 clients by `/64` and evict the oldest inactive key instead of flushing or growing unboundedly.
- Pens (audit H3): the registrar and step-ca never run as root. A pen set up as root (every hosted pen) now runs them as user 65532 ("nonroot"), and pens raised as root before this change move to it on their next start. The files they use are handed over, and the public certificates are made readable. A person running their own pen still runs them as themselves. The Caddy containers still run as root; that's a separate change.
- Hosting (audit H9, H4): nightly backups never include `pki/offline/`, so a self-hosted root key that hasn't been moved off yet can't end up in backups. The sign-up broker, which can drive Docker, has no internet access unless push notifications are on (`hogman-host signup-notify`), its only outbound use.
- Registrar (audit H7): two owners demoting each other at the same moment can no longer leave a pen with no owner (one conditional update, under the service lock), and an invite carries its maker's authority. A maker's open invites are revoked when their role shrinks, and redemption re-checks that the maker may still hand out that role.
- The pen's CA offers only TLS-ALPN on 443 (`http-01` removed, matching HTTPS-only) and refuses certificates for IP addresses or wildcard names (step-ca issuance policy). The portal asks for TLS-ALPN explicitly.
- HSTS (one year) on the website, every pen's public host, the sign-up page and the home page.
- CI: e2e always reports (a docs-only change skips the suites), so its checks can be required on main; GitHub Actions pinned to commit SHAs; `govulncheck` on every module for PRs, main and weekly; Dependabot for Go modules, base images and Actions. Secret scanning, push protection and Dependabot security updates are on for the repository.

### Changed
- `hogman-join share`: background shares (`--background`) now register per-share login services on macOS (`LaunchAgent`) and Linux (`systemd --user`, printing a `loginctl enable-linger` hint when linger is off) so shares survive restarts; `--no-service` keeps them temporary, foreground `share` / `share stop` / `leave` clean up the service, `share list` shows autostart status, and `hogman-join update` restarts managed shares cleanly with rollback on failed binary swap. Updated share, join, and README docs.
- `hogman-join`: support multiple simultaneous pens in browsers with a combined `/proxy.pac` served dynamically by each running pen agent across all installed pens; macOS updates Hogman-managed automatic proxy settings with a versioned `?v=` URL when joining or leaving (still leaving foreign/corporate PACs untouched), while Linux and Windows print combined-PAC guidance. Updated join and FAQ docs and added unit and host e2e coverage.
- No account recovery (decision D-16, replacing D-12's passkey plan): no recovery page, no recovery passkeys. Someone who loses every device gets a new invite and a new account, and a keeper gives it back its role. The herd gains **Make owner** and **Make admin** for owners, so a pen can have a second owner from the home page; a lone owner sees a warning to make one. `GET /api/me` tells owners how many owners the pen has. Nobody can make a personal device key for someone else any more, not even the server's own tool (`device key <handle> personal` now only works for a member's very first device, which is how a new pen's owner gets in). FAQ, keeper docs, sign-up page and home page say so.

### Security
- `hogman-join`: the agent's own `/status` and `/proxy.pac` answer only requests addressed to its loopback address or `localhost` (no DNS-rebinding reads); `leave` removes the computer's own device from the pen (so old devices don't pile up) and no longer fails on shares that never came up; `share` no longer looks at the system Tailscale; `--tailscale` explains that it was removed. FAQ: what Hogman deliberately doesn't do, reworded, and "What if I lose my laptop?" (no recovery on request, ever: D-12), and that a copied device file works elsewhere until the device is removed (hardware locking is Phase 2: D-13, D-14). `leave` removes the certificate before the device, so cancelling the password prompt leaves the computer still on the pen.
- Port 80 removed: members reach servers, and the pen's home page, on 443 only (infra keeps 53 for DNS and 9000 for the CA). The join agent answers `http://` pen addresses itself with a 308 redirect to HTTPS instead of carrying HTTP into the pen (its reverse proxy is gone); shares no longer listen on 80 and get certificates over TLS-ALPN on 443.
- HTTPS only (decision D-11): members reach servers on ports 443 and 80 only (the access policy no longer grants `*`); the join agent's proxy carries only ports 443 (CONNECT) and 80 (HTTP); computers join only through the agent: joining through the system Tailscale app is removed (it put every program on a member's computer onto the pen and gave the pen's control server that computer's DNS: one member widening the whole pen's risk), and a computer still on a pen that way is asked to leave and rejoin. Joining a whole computer as a "server" is removed too (it forwarded the pen's 80/443 to whatever listened on that machine): server links are now marked `for=share` and only work with `hogman-join share`; a plain join refuses them before using the key, and an old unmarked link is refused and undone after joining. The home page's "Names for your servers" card and Caddy recipe, and the docs' "Your own web server" and "Advanced" pages, are gone; shares name themselves, and an existing web server is shared by its port. The FAQ says what Hogman deliberately doesn't do. The own-connection design (root daemon, TUN, DNS changes) will not be built.
- `hogman-join` side-by-side agent (and `share`) now dials only devices the pen's own node knows (`WhoIs`), whatever the pen's DNS answers. tsnet's `Dial` falls back to the computer's own network for non-peer addresses, so a hostile pen's DNS could have pointed a pen name at `127.0.0.1`, the LAN, or another tailnet's 100.x address and had the agent connect there (found in the red team of the own-connection design).
- Enforce same-origin (`Origin` / `Sec-Fetch-Site`) and `Content-Type: application/json` checks on mutating mesh API endpoints to block CSRF from member-hosted or external sites.
- Restrict `server` devices on the mesh API to `GET /api/me` (minimal `{member, this_device, zone, network}` payload), `GET /api/directory`, and acting on themselves only (claim a free name or one already pointing at them, release names that point only at them, remove themselves), returning `403` on everything else, including `/api/admin/*`.
- Switch Headscale IP allocation to `random`, verify caller mesh IPs against live Headscale nodes in `identify()`, harden admin-vs-owner RBAC and subdomain cleanup, rate-limit `POST /hogman/v1/redeem`, cap per-member invites/keys/names, revoke open keys on suspend, and configure server timeouts (PR #5).
- Add strict anti-framing (`X-Frame-Options: DENY`, `frame-ancestors 'none'`), CSP (`script-src 'self'`, `style-src 'self'`), `nosniff`, and `no-store` headers on `portal` and `/join`, block `/api/*` and `/swagger*` on edge proxies, bind `edge-behind-front` strictly to `{$PUBLIC_HOST}`, and enable `trusted_proxies_strict` + forward `X-Forwarded-For: {client_ip}` on `/hogman/*` behind the shared front door (PR #6).
- Harden `hogman-join`: reject URL credentials, require full IPv4/IPv6 exclusions and valid cert dates on the root CA, validate `/hogman/v1/network` metadata, store temp root certs at `0700`/`0600`, restrict proxy `forward()` to `http`, and quote systemd `ExecStart` paths (PR #7).
- Validate pen names, hostnames, and IPv4 addresses strictly in `deploy/hogman-host` and `core/hogman`, tighten host/pen secret directory and file permissions (`700`/`600`), add SSH lockdown verification and `sshd` key-only config in `deploy/bootstrap.sh`, scrub personal examples from `deploy/`, and add `mem_limit`, `pids_limit`, `read_only`, non-root user, and capability drops in `core/compose.yaml` (PR #8).
